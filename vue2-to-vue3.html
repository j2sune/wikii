코드 구성 — 종류별로 나누던 코드를 기능별로 모은다

Vue2는 data / computed / methods처럼 종류별 칸에 나눠 넣습니다. 기능이 커지면 한 기능의 코드가 여러 칸에 흩어집니다.

// Nuxt 2 (Vue2) · Options API — 종류별 칸에 나눠 쓰기
export default {
  data() {
    return { count: 0 };
  },
  computed: {
    double() {
      return this.count * 2;
    },
  },
  methods: {
    inc() {
      this.count++;
    },
  },
};

Vue3의 Composition API(<script setup>)는 기능 단위로 모아 씁니다. Nuxt 3는 ref, computed 같은 것도 자동으로 import해줍니다.

<!-- Nuxt 3 (Vue3) · Composition API — 기능별로 모아 쓰기 -->
<script setup>
const count = ref(0);
const double = computed(() => count.value * 2);
const inc = () => count.value++;
</script>
✓
기존 Options API도 그대로 쓸 수 있어서 한 번에 다 바꿀 필요는 없습니다. 새로 만드는 화면부터 적용하면 됩니다.

공통 기능 재사용 — mixin (섞어 넣기) 대신 composable (함수로 꺼내 쓰기)

여러 화면이 같이 쓰는 기능(목록 불러오기, 로그인 확인 등)을 묶어 두는 방법이 바뀝니다.

Vue2

mixin (섞어 넣기)

  • 여러 mixin의 이름이 겹치면 조용히 덮어씀
  • this.xxx가 어디서 왔는지 추적이 어려움
  • 재사용할수록 복잡해짐

Vue3

composable (함수로 꺼내 쓰기)

  • 필요한 값만 골라서 꺼내 씀
  • 값의 출처가 코드에 그대로 보임
  • 평범한 함수라 테스트하기 쉬움
// composables/useOrderList.js — Nuxt 3는 composables/ 폴더를 자동 import
export function useOrderList() {
  const list = ref([]);
  const loading = ref(false);

  async function reload() {
    loading.value = true;
    list.value = await $fetch("/api/orders");
    loading.value = false;
  }

  return { list, loading, reload };
}

// 사용하는 쪽 — 무엇을 가져오는지 명확
const { list, loading, reload } = useOrderList();

반응형 — 데이터가 바뀐 걸 알아채는 방식이 바뀐다

반응형은 데이터를 바꾸면 화면이 자동으로 바뀌는 것을 말합니다. Vue3는 데이터 변경을 더 넓게 감지하는 방식(Proxy)으로 바뀌어서, Vue2에서 필요했던 우회 코드($set)가 필요 없어집니다.

// Vue2 — 바꿔도 화면이 그대로
this.list[0] = item;            // 배열 인덱스 대입
this.user.nickname = "새 값";    // (원래 없던 속성이면) 새 속성 추가
// 우회 코드가 필요했음: this.$set(this.list, 0, item)

// Vue3 — 바로 화면에 반영
list.value[0] = item;
user.nickname = "새 값";

큰 데이터에서 특히 유리합니다.

  • Vue2는 데이터를 넣는 순간 객체 전체를 끝까지 돌면서 감시 대상으로 등록합니다. 큰 목록을 받으면 이 작업 자체가 느리고 메모리를 많이 씁니다.
  • Vue3는 실제로 쓰는 부분만 감시합니다.
  • 감시할 필요 없는 큰 데이터는 shallowRef / markRaw로 명시적으로 뺄 수 있습니다.

성능 — 프레임워크 차원에서 가벼워지는 세 가지

영역Nuxt 3 (Vue3)에서 달라지는 점

03

우리 서비스 관점 — 뒤로가기 상태 유지, 선택지가 넓어진다

지금 · Nuxt 2

화면을 통째로 보관

  • keep-alive로 화면 전체를 메모리에 붙잡아 둠
  • 캐시할 화면 목록을 레이아웃 한 곳에서 관리
  • 방문한 화면이 쌓일수록 무거워짐
  • 안 보이는 화면의 watch · 타이머도 계속 동작

Nuxt 3

필요한 만큼만 보관

  • ① 페이지별 선택 (keep-alive) — 필요한 페이지만 보관. 보관된 화면은 watch가 계속 돎
  • ② 데이터만 캐시 (keep-alive 아님) — 화면은 정리, 데이터만 보관. watch · 타이머도 같이 정리

지금 (Nuxt 2)

<!-- layouts/default.vue -->
<Nuxt keep-alive :keep-alive-props="{ include: ['OrderList'] }" />

Nuxt 3 ① 페이지별 선택 (keep-alive)

각 페이지가 "나는 캐시해 줘"를 직접 선언합니다. 레이아웃의 이름 목록을 맞출 필요가 없습니다. 선언 위치만 바뀐 같은 keep-alive라서, 보관된 화면의 watch는 지금처럼 계속 돕니다. 대신 보관 범위를 필요한 페이지로 줄일 수 있습니다.

<!-- pages/orders/index.vue -->
<script setup>
definePageMeta({ keepalive: true });
</script>

Nuxt 3 ② 데이터만 캐시 (keep-alive 아님)

화면은 버리고, 받아온 데이터(JSON)만 기억해 뒀다가 돌아오면 그걸로 바로 그립니다. 떠날 때 화면이 정리되므로 watch · 타이머 · 리스너도 같이 정리됩니다.

  1. 목록 진입 — 서버에서 받아 데이터를 이름표(key)와 함께 보관
  2. 상세로 이동 — 목록 화면은 비움, 데이터는 남김
  3. 뒤로가기 — 요청 없이 보관된 데이터로 바로 표시

원리 — 어디에 보관되나

  • Nuxt 3에는 기본 내장 보관함 nuxtApp.payload.data가 있습니다. useAsyncData("orders", …)로 받은 결과는 payload.data["orders"]처럼 이름표(key)별로 저장됩니다.
  • 이 보관함은 원래 서버에서 받은 데이터를 브라우저로 넘기는 통로입니다. 첫 진입 때 서버가 받은 데이터를 HTML에 담아 보내고(__NUXT_DATA__), 브라우저가 이걸 채워서 같은 요청을 두 번 하지 않습니다.
  • 페이지 이동은 새로고침 없이 화면만 바뀌므로(SPA), 이 보관함은 탭이 열려 있는 동안 브라우저 메모리에 유지됩니다. 새로고침하거나 새 탭을 열면 비워집니다(localStorage나 서버 저장이 아님).
  • 기본 동작은 페이지 이동 시 다시 요청입니다. getCachedData 옵션으로 "보관함에 있으면 그걸 써"라고 지정하면 뒤로가기 때 요청 없이 바로 그립니다.
Nuxt 2Nuxt 3
페이지 이동 후 데이터asyncData가 매번 다시 실행, 이름표 붙은 보관함 없음같은 보관함에 key별로 유지
뒤로가기 즉시 표시Vuex에 직접 저장하는 코드를 짜거나 keep-alive로 화면째 보관getCachedData 옵션으로 가능

데이터 캐시는 Nuxt 2에서도 직접 만들면 가능합니다. 다만 화면마다 아래 같은 코드를 짜고 key 관리 · 유효 시간을 직접 만들어야 합니다. Nuxt 3는 이게 기본 내장이라 옵션 하나로 됩니다. (Vue3 자체 기능이 아니라 Nuxt 3의 기능입니다.)

// Nuxt 2에서 직접 구현하는 예
async asyncData({ store }) {
  if (!store.state.orders.list.length) {   // 보관본이 없을 때만
    await store.dispatch("orders/fetch");  // 요청해서 Vuex에 저장
  }
},
computed: {
  orders() { return this.$store.state.orders.list; },
},

keep-alive는 화면 전체(요소 · 임시 상태)를 붙잡아 두지만, 데이터 캐시는 가벼운 데이터만 남겨서 메모리 부담이 적습니다. 데이터가 오래되지 않게 유효 시간을 두거나, 수정 · 삭제 후 clearNuxtData("orders")로 지우면 됩니다.

<script setup>
const nuxtApp = useNuxtApp();

const { data: orders } = await useAsyncData(
  "orders",                         // 이 키로 데이터를 캐시
  () => $fetch("/api/orders"),
  {
    // 이미 받아둔 데이터가 있으면 다시 요청하지 않고 그대로 사용
    getCachedData: (key) => nuxtApp.payload.data[key] ?? nuxtApp.static.data[key],
  },
);
</script>

필터나 페이지 번호는 URL 쿼리(?page=3)에, 스크롤 위치는 라우터의 스크롤 복원에 맡기면 됩니다.

Nuxt 2 모듈 · 플러그인Nuxt 3 대응 버전호환 여부 확인 필요

Nuxt 2 → 3는 Vue 문법 변화에 더해 Nuxt 자체 API도 바뀝니다. 쓰고 있는 Nuxt 모듈이 Nuxt 3를 지원하는지 먼저 목록을 뽑아 보는 게 좋습니다.

단계별 전환 — 한 번에 갈아엎지 않는다

  1. Nuxt Bridge — Nuxt 2 프로젝트에서 Composition API와 Nuxt 3 스타일 API를 먼저 써볼 수 있는 공식 중간 단계.
  2. 문법 · 모듈 정리 — 필터, 이벤트 버스를 걷어내고, 모듈의 Nuxt 3 호환 여부를 확인합니다.
  3. 상태 · 데이터 — Vuex → Pinia, asyncData → useAsyncData로 옮깁니다.
  4. Nuxt 3 전환 — Swiper 등 라이브러리를 최신 버전으로 교체합니다.
